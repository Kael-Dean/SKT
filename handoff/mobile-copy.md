## 10. สิ่งที่ต้อง lead ตัดสิน (escalate)

1. mobile label `น้ำหนักเข้า/น้ำหนักออก` แทน `น้ำหนักก่อนชั่ง/หลังชั่ง` (§6.1) ถ้าไม่อนุมัติ builder ใช้ label เดิมทั้งสอง viewport
2. คอลัมน์ "เสนอ" ใน §9 ทั้งหมด (ตัด "กรุณา", ตัด `asso_id`/`species`/`variant`) ปัจจุบัน default = เดิม
3. ประโยค "คันที่บันทึกแล้วจะไม่ถูกบันทึกซ้ำ" (§4.2) ต้องยืนยันพฤติกรรม submit loop ก่อนใช้ มิฉะนั้นเป็นคำสัญญาที่ระบบไม่รับประกัน
4. `ErrorState` default message (§5) เปลี่ยนหรือไม่ (กระทบหน้า HR ด้วย)
5. Toast กดได้ / `opts.action` ใน `toast.js` (§3) เป็นงาน design-system-engineer

---

สรุป: ไฟล์นี้ให้ string ครบ 10 กลุ่มสำหรับ Buy/Sales stepper, sticky bar, toast แทน alert 12 จุด, ResultSheet, empty/loading/error ของทุกหน้าใน §C, label ย่อ, picker, Home strip และ validation ต่อขั้น พร้อม glossary ชื่อฟิลด์ให้ toast "ยังไม่ได้กรอก" ประกอบเองได้
Default ทุกจุดคือข้อความเดิม คอลัมน์ "เสนอ" และรายการ §10 รอ lead อนุมัติก่อน builder นำไปใช้
หลัง WP3 เสร็จ จะ audit copy จริงที่ 390px แล้วส่ง diff ให้ lead ตามแผน WP4
