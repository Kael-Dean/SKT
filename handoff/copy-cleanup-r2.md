## 3. ที่ไม่ได้แก้ + เหตุผล

- **ข้อความที่มาจาก master data ของ backend** เช่น ชื่อฟอร์ม `สด - ERM`, ชื่อสภาพ/โปรแกรม/ประเภทธุรกิจ, `prod_name`: อยู่ในฐานข้อมูล ไม่ใช่ frontend ต้องแก้ที่ข้อมูล
- **`#ย่อย` → brief ให้ใช้ `ชั้นย่อย`**: ค่าในคอลัมน์คือ `sub_order` (1/2) ซึ่งโค้ด OrderCorrection ผูกกับ `weight_1/price_1` (พ่วงหน้า) และ `weight_2/price_2` (พ่วงหลัง) ไม่ใช่ชั้นย่อยของข้าว ถ้าใช้ "ชั้นย่อย" จะสื่อผิด จึงใช้ `ลำดับพ่วง` / badge `พ่วง 2` แทน **ต้องยืนยันกับ backend ว่า 1 = พ่วงหน้า, 2 = พ่วงหลัง** ถ้าใช่ ควร map เป็นคำ `หน้า`/`หลัง` ในรอบหน้า
- **StockTransferIn ชื่อคลัง**: `/transfer/pending/incoming` ส่งแค่ `from_klang`/`to_klang` เป็นเลข id ตอนนี้แถว "จากคลัง/ไปคลัง" จะถูกซ่อนจนกว่า backend เพิ่ม `from_klang_name`/`to_klang_name` (frontend รองรับไว้แล้ว) ไม่ได้เพิ่มการโหลดรายชื่อคลังเองเพราะเป็นการแก้ logic
- **ข้อความ `กรุณา…` ใน validate เดิม**: คงไว้ตาม V2
- **`window.confirm` ใน StockTransferMill** (เปลี่ยนสเปคตอนมีรายการในล็อต): แก้แค่ถ้อยคำ การเปลี่ยนเป็น `<ConfirmDialog>` เป็นงาน logic
- **em dash ในชื่อรายงาน P01–P19** (`P01 — …`) และ placeholder `— เลือก… —`: เป็น pattern เดิมทั้งแอป ไม่ใช่ศัพท์ dev
- **Buy / Sales / `src/components/*`**: นอก ownership (คนอื่นแก้อยู่) ยังมี `ล็อกสเปกจากฟอร์มสำเร็จรูป` ใน BuyCustomerSection / SalesCustomerSection และ `เลือกฟอร์มสำเร็จรูปให้มีสเปกสินค้า` ใน buyValidation.js

## 4. คำถามที่ควรถามลูกค้า

1. **FID**: พนักงานเรียกว่า "เลขทะเบียนเกษตรกร" หรือพูดว่า "FID" จนชิน? (ตอนนี้ใช้ภาษาไทยทุกจุด)
2. **TGS**: ใช้คำว่า "รหัส TGS" ถูกไหม หรือเรียก "รหัสสมาชิก ธ.ก.ส."?
3. **ล็อต / LOT**: เอกสารส่งสีจริงเขียน "LOT" หรือ "ล็อต"?
4. **gram → กรัม**: ช่องคุณภาพข้าวหน่วยเป็นกรัมจริงไหม (ค่าที่กรอกคือน้ำหนักข้าวเต็มเมล็ดในตัวอย่าง?) หรือเป็นคะแนน
5. **ลำดับพ่วง**: ในออเดอร์ขาย ย่อย 1/2 = พ่วงหน้า/พ่วงหลัง ใช่ไหม
6. **ชื่อรายงานแผน 01–18**: คำแปลเป็นร่าง โดยเฉพาะ "Aux" (ใช้ "ค่าใช้จ่ายเสริม") ขอชื่อที่ใช้ในเอกสารแผนจริง
7. **"รายงานธุรกิจรวบรวมผลผลิต"** (เดิม Phase 1): กล่องนี้มีทั้งรายงานซื้อขายข้าว ทะเบียนหุ้น และสมาชิก ชื่อนี้ครอบคลุมพอไหม หรือควรเป็น "รายงานสหกรณ์"
8. **เลขคำขอ / เลขออเดอร์ `#123`**: พนักงานใช้เลขนี้อ้างอิงจริงไหม
